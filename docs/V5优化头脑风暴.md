## 1. 用户界面与交互体验

### 1.1 全局「正在播放」指示统一化
- **思路**：三主题各自的列表行 active 态逻辑不同（player.js 的 `active` 类、fb2k 的 `playing` 类、am-render 自行管理），抽成共享的 `markPlayingRow(path)` 最小封装（只做"查找行 + 切换类名"）
- **预期效果**：切主题后视觉语言一致；减少三套维护成本
- **技术挑战**：三主题 DOM 结构差异大，抽象层太薄没价值、太厚限制主题个性

### 1.2 键盘可达性补全
- **思路**：快捷键目前集中在播放控制/外壳（Ctrl+M、N 等），列表区补键盘导航（↑↓ 选曲、Enter 播放、Ctrl+F 聚焦搜索）
- **预期效果**：长曲库场景效率明显提升；补齐无障碍短板
- **技术挑战**：窗口化渲染（虚拟列表）下焦点管理要和 DOM 回收配合，处理不当会丢焦点

### 1.3 无损鉴别结果的沉浸呈现 ⭐
- **思路**：V4.0.5 四方法报告目前只有文字列表；viz 页签加一张小型频谱剖面图（`profileDb` 24 带数据现成，HTML 导出报告里已有画法，渲染层照搬）
- **预期效果**：用户"看见"砖墙截止，比读扣分理由直观得多
- **技术挑战**：低，纯前端；注意明暗主题自适应（参照 soak-8h.svg 的 @media 做法）

### 1.4 迷你模式快捷操作密度
- **思路**：迷你条目前只有传输控制，加右键菜单（收藏/播放模式/退出）
- **预期效果**：迷你模式不再"残废"
- **技术挑战**：窗体高度限制，只能走菜单不能加控件

## 2. 播放性能与流畅度

### 2.1 引擎 RPC 批量读取合并
- **思路**：渲染层进度轮询（progress.stats）目前固定间隔单发，把 stats + 队列状态合并为一个复合 RPC
- **预期效果**：IPC 往返减半；对播放零风险
- **技术挑战**：低，但需保持字段向后兼容

### 2.2 窗口化列表滚动预取调优
- **思路**：am-dom.js 曲目表窗口化按滚动位置重建可见行，加坡度（overscan ±2 屏）+ 行高缓存
- **预期效果**：快速甩滚不闪白
- **技术挑战**：变高行（多行标题）会破坏"固定行高×索引"定位假设，需实测决定

### 2.3 封面懒加载磁盘缓存 ⭐
- **思路**：ensureCover 每次启动重新走 meta 通道取封面，加一级 hash-keyed 磁盘缓存（%appdata%/covers/）
- **预期效果**：二次启动曲库封面秒出，meta 通道压力锐减（benchmark 显示 1 万轨 meta 是启动瓶颈之一）
- **技术挑战**：缓存失效策略（文件 mtime 变化）与磁盘占用上限

## 3. 功能丰富性与实用性

### 3.1 无损鉴别「整库体检报告」
- **思路**：V4.0.5 已有三范围检测 + HTML 报告导出；报告头部加汇总统计（疑似分布直方图、按文件夹聚合）
- **预期效果**：从"逐曲判定"升级为"曲库健康度体检"，差异化能力
- **技术挑战**：几乎无，数据都在；大曲库下报告 HTML 体积需分页（20 万轨）

### 3.2 播放定时渐弱淡出 ⭐
- **思路**：已有播放定时，补"定时停止前渐弱淡出"（调引擎 gain 斜坡而非硬切）
- **预期效果**：睡前场景体验闭环
- **技术挑战**：引擎侧 gain 斜坡要和 crossfade 状态机协调，避免冲突

### 3.3 「相似歌曲」智能推荐
- **思路**：metaCache 已有响度/BPM/调性（节奏徽章），以当前曲为种子做相似推荐（BPM±10 + 同调性 + 响度接近）
- **预期效果**：零云端纯本地个性化推荐，与每日推荐互补
- **技术挑战**：BPM/调性覆盖率取决于分析进度，需"先补算再推荐"引导流程

## 4. 资源占用与运行效率

### 4.1 soxr 重采样按需激活 ⭐
- **思路**：Bit-perfect 链路已实现"采样率匹配则跳过 SRC"；进一步：SRC 未激活时不初始化 soxr 上下文
- **预期效果**：8h 长稳基线 53-64MB 有望再降；独占用户纯收益
- **技术挑战**：低；首次激活延迟不能产生可闻 gap

### 4.2 超大曲库的专辑网格窗口化
- **思路**：FB2K/AM 曲目表已窗口化，但侧栏专辑网格在 1 万+ 专辑时是全量 DOM，按行虚拟化
- **预期效果**：超大曲库渲染层内存和布局耗时显著下降（benchmark 有现成对照数据）
- **技术挑战**：网格布局窗口化比线性列表复杂

### 4.3 沙箱子进程空闲休眠
- **思路**：sources 子进程（V4.0.3 加固后）常驻；空闲 30 分钟自动退出、有请求再拉起
- **预期效果**：待机内存 -20~30MB
- **技术挑战**：已有退避重建机制可复用；小心"请求唤醒"竞态（启动中请求需排队）

## 5. 兼容性

### 5.1 老 CPU 指令集兜底
- **思路**：.NET 单文件发布默认面向现代 x64；CI 加兼容档，或检测不支持时明确报错而非闪退
- **预期效果**：十年前机器也能跑
- **技术挑战**：需老机器实测；CI 无法覆盖

### 5.2 网络流缓冲水位自适应
- **思路**：流媒体缓冲策略目前固定值，按网络抖动（近期欠载次数）动态调大 prebuffer
- **预期效果**：弱网欠载减少（长稳框架已有欠载计数，直接当反馈信号）
- **技术挑战**：水位调大会拉长起播时间，需权衡上限

## 6. 代码结构与可维护性

### 6.1 主题三件套公共层抽取（大手术）
- **思路**：V4.0.4 拆完 AM 五片后，player.js/fb2k.js 仍是 2000+ 行单文件；三主题共用部分（播放控制绑定、进度条逻辑、弹层管理）下沉为 `theme-common.js`，主题文件只留视图差异
- **预期效果**：新主题成本从"抄 2000 行"变"写一个视图层"；bug 修一处三主题受益
- **技术挑战**：无自动化测试兜底，复用 amchaifenwork 工作区方法论（切片拼接逐字节一致 + 引用审计 + vm 烟测）

### 6.2 主进程 main.js 模块化
- **思路**：main.js 已近千篇注释分区清晰（诊断/统计/无损鉴别/迷你模式…），按分区拆 `main/ipc/*.js`，main.js 只做装配
- **预期效果**：冲突率下降，PR review 聚焦
- **技术挑战**：低，纯搬迁；loadStore/saveStore 等共享闭包依赖需显式注入

### 6.3 检测/分析能力下沉引擎（远期，V5 再议）
- **思路**：无损鉴别目前是主进程 JS FFT（V4.0.5 手写 radix-2）；远期把 STFT 累计器下沉到 .NET 引擎侧（C# SIMD + 并行），JS 只做规则判定
- **预期效果**：20 万轨整库体检大幅提速；JS 侧 CPU 占用归零
- **技术挑战**：新增 RPC 通道协议与进度事件流；引擎测试集需扩展

## 7. 音质与 DSP 深化

### 7.1 AutoEq 耳机校正导入 ~~（V4.2.0 已落地）~~
- **状态**：✅ V4.2.0 落地（打包子集方案），V4.3.1 升级为官方全量库：8849 型号 / 1.78MB（`autoeq-subset.json`，`scripts/autoeq-build.js` 默认全量构建、`--curated` 保留精选模式）；低架/高架以峰值近似、10 段裁 8 段、前级由自动补偿接管。在线兜底查冷门型号已无必要

### 7.2 AutoEq 结果文件自定义导入
- **思路**：V4.2.0 子集只有 189 款精选型号，子集外型号目前只能手动逐条加频段；加「导入 AutoEq 结果（选 ParametricEQ.txt 文件 / 粘贴文本）」入口，把构建脚本里的解析+转换规则（LSC/HSC→峰值近似、按 |增益| 裁 8 段）搬到渲染层复用
- **预期效果**：AutoEq 全库 5000+ 型号及用户自建校正全部可用，彻底补齐子集覆盖短板
- **技术挑战**：低；解析正则现成（`Filter N: ON PK|LSC|HSC Fc .. Gain .. Q ..`），注意非法文件容错提示

### 7.3 真 Native DSD（ASIO DSD 扩展）✅ 已落地 V4.3.12（实验）
- **实现**：新增 `engine/src/src/AsioDsd.cs`（AsioNativeDsdOutput）——NAudio `AsioDriver.Future()` 本就公开，直接 `kAsioCanDoIoFormat`/`kAsioSetIoFormat`(0x23112004/0x23111961) 切 DSD 模式 → SetSampleRate(DSD 位率) → CreateBuffers 后按 GetChannelInfo 回报的位序送裸 DSD 位流（DSF 天然 LSB1；MSB1 驱动查表按位翻转）。RT 回调只 memcpy，文件 IO 在独立供数线程（预读队列 ×24）；欠载/曲终填 DSD 静音花纹 0x69/0x96（绝不填 0，满幅直流烧喇叭）。参考：foo_dsd_asio（ASIOProxy）+ ASIO SDK 2.3「Sony DSD Support」
- **集成**：Engine.Playback.cs TryPlayNativeDsd（不占 _backend 槽位，独立 _asioDsd 字段；StopAll/Pause/Resume/TickPosition 特判）；设置 → 音频 → DSD 输出方式选「Native（ASIO DSD·实验）」
- **顺手修的 DoP bug**：Resume 旧条件要求 `_source != null`，DoP 模式下恒为空 → **DoP 暂停后恢复无效**；已改为 `_source != null || _dopActive`
- **待验证**：真机矩阵（Cayin/MOONDROP 等 XMOS 系）；缓冲尺寸语义（样本 vs 字节）若某些驱动解释不同会周期爆音，需实测；48k 系 DSD（3.07MHz）未测
